Layer 1 · Sense

No single sensor can tell sabotage from a fox

The bet is that combinations plus context (wind, rain, SCADA events, the maintenance schedule) explain most alarms, and the robot plus a human handle the rest. That is unproven.

How it connects

Everything decides on site; only advisories cross into the DSO's network

Sensing, classification and evidence capture keep running when the link drops, and queue for sync. The operator still needs a link to confirm, so a backup alert channel is part of the design.

Sensor node · one per fence panel

Fence node: hear it, feel it, sign it

An ESP32-S3 samples a low-noise accelerometer and an I²S microphone, computes features on board (RMS, peak, band energy, impact count) and sends small signed messages instead of raw streams. Power and data come over one shielded PoE cable; LoRa is a narrow backup for alarms only.

Edge box · one per site, in the control building

Edge box: powered from the station battery, isolated from everything

Substations already have a 110 V DC battery system that rides through outages. The edge box takes power from it through an isolated converter, so Grid Sentinel keeps watching during exactly the events it exists for.

Layer 2 · Understand

Learn what is normal, explain it away, escalate the rest

Real attacks are too rare to train an "attack classifier". The pipeline instead learns each site's normal and the common benign causes, and sends anything it cannot explain to the robot and a human.

The accuracy trap

With rare events, "accuracy" means nothing. A system that never alarms is 99.8% accurate if 2 in 1,000 events are real. Move the sliders to see what precision and false alarms per week actually look like.
